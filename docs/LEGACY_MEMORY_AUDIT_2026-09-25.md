## Changed since capture

The brief's dates do not match git. HEAD has 252 commits, but `git rev-list --count v1.1.9..HEAD` is **32**, not 65. v1.1.9 is commit `21a10b3`, dated September 11, 2026. The claims' recorded capture is September 4 and their Auto behavior is already visible in `7917207` on August 30. Treat these as pre-standalone memories, not a v1.1.9 snapshot.

Changes specifically between v1.1.9 and v1.1.19:

- `0d01cde` (September 20): onConnect rejects unauthorized controllers; Gearhead recognition now checks UID/package ownership and signing certificates through MediaControllerAccess. A package-name-only recipe would bypass the current design. Affects 8bfea689 and bfb2e00b.
- `e9ece3c` (September 19): adds thumbs-up/down commands and defined icons. The old two-action description is incomplete. Affects 48fe4ace and duplicate 368f464c.
- `6fc31f7`: continuous radio fallback uses local.radioActive and keeps radio separate from the general automatic mix. The persisted isManual/isRadio distinction survives; no new duplicate of the existing curated radio algorithm claims was created. Affects e403fbc1 and the current advance path described by 9750f4df.

Changes after actual capture but before v1.1.9:

- `e2afecd` / `428f4a8`: standalone direction became documented architecture and then implemented personal playback/nearby rooms. The service switched to typed core events/queue operations. refreshAndroidAutoQueue gained the profile-reload invalidation exception. Affects 4321a9a7, 63b39584, 788abee4, b8c6d1f6, be992f2d, d73192c7, e403fbc1, e773b1e7.
- `a23187f`: automatic queue fallback via dequeueWithAutomaticFallback; the server HTTP dequeue recipe is not the current playback path.
- `8d988b3`: projection state replaces controller presence as the lasting Auto-authority signal, because legacy controllers can outlive projection. Affects bfb2e00b.
- `157fdcf`: removes RemoteHarmonicastCore and server implementation, replaces obsolete architecture documentation, and leaves internet guest control/public relay outside scope. Affects server queue, rendezvous, deferred standalone and guest-auth proposals. Acoustic QR was a historical proposal; this audit does not promote it as implemented or currently approved.

## Memory vs. history

I have no independent recollection of earlier sessions available in this task, so none was used as evidence. The discrepancies are between the supplied legacy memory/brief and the checked commits:

- “Captured around v1.1.9” disagrees with the September 4 capture and September 11 v1.1.9 commit.
- “One ordered server queue” is stale: Android local.queue owns upcoming tracks.
- “Only refresh after deliberate Auto actions” omits profile reload, introduced in 428f4a8.
- “Gearhead always takes control on connection” omits projection-state gating and caller authentication.
- “Standalone remains deferred” disagrees with implemented standalone architecture and server removal.
- A surviving comment in refreshAndroidAutoQueue says the Up next surface is kept current by a “timeline update below”; 7917207 removed that synchronization call and function. Executable code uses the current-track-only timeline. The comment was not accepted as proof of a full queue timeline.
- The exact #2192 upstream attribution and original user quotations are not independently proved by repository history. The promoted timeline detail explicitly labels the issue reference as legacy provenance, not a verified upstream fact.
